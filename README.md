# Company Taskboard — корпоративный таск-менеджер

Стартовая рабочая версия внутренней системы для проектов, задач, канбана и визуальной доски. Проект подготовлен для локального развёртывания, **не является готовым промышленным релизом**.

## Реализовано

- Учётные записи администратора и пользователей; вход по паролю с Argon2id и серверной сессией.
- Системные роли SUPER_ADMIN / ADMIN / USER; проектные OWNER / MANAGER / MEMBER / VIEWER.
- Проекты, участники, четыре канбан-колонки.
- Задачи, приоритеты, назначение исполнителя через API, изменение карточек, перемещение по колонкам.
- Основная визуальная доска с заметками, текстовыми блоками, ссылками на задачи и стрелками.
- Раздел администратора с базовой статистикой.
- PostgreSQL, Prisma, REST API, Docker Compose.

## Первый запуск разработчика

1. Установите Node.js 22+, PostgreSQL 17 и npm.
2. `cp .env.example .env` — задайте уникальные длинные пароли; для локальной разработки установите `WEB_ORIGIN=http://localhost:5173` и `DATABASE_URL` на локальную БД.
3. `npm install`
4. `npm run db:generate -w @taskboard/api`
5. `npm run db:migrate -w @taskboard/api`
6. `npm run db:seed -w @taskboard/api`
7. В двух терминалах: `npm run dev:api` и `npm run dev:web`.
8. Откройте `http://localhost:5173` и войдите под администратором.

## Docker

1. Создайте `.env` на основе `.env.example` и установите сильные пароли.
2. Первичная миграция уже находится в `apps/api/prisma/migrations`.
3. `docker compose up --build -d`
4. `docker compose exec api sh -lc 'cd apps/api && npx tsx prisma/seed.ts'`
5. Для локальной HTTP-проверки установите `WEB_ORIGIN=http://localhost:8080` в `.env` и пересоздайте API-контейнер. По умолчанию UI доступен **только локально на сервере**: `http://127.0.0.1:8080`. Для сотрудников нужен отдельный внутренний HTTPS reverse proxy с доверенным сертификатом и корректным WEB_ORIGIN. Не публикуйте HTTP напрямую в LAN.

## Ограничения этого среза

- Нет полноценного одновременного редактирования, комментариев, файлов, оповещений и аудита.
- Фронтенд пока не реализует интерфейс назначения пользователей в задачи, хотя модель и API поддерживают назначение при создании.
- WebSocket, CSRF-токены, резервное копирование и законченный HTTPS deployment ещё не реализованы.
- API поддерживает лишь часть будущего ТЗ. Важно завершить тесты безопасности и нагрузочные испытания до эксплуатации.
- Первичная миграция подготовлена, но её применение пока не проверено на PostgreSQL в этой среде.

См. [docs/ROADMAP.md](docs/ROADMAP.md).
